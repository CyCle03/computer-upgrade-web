# usemap-restore-backend

The backend server for the web remake of the StarCraft use-map **"Computer Upgrading"**.
It handles daily 100-floor raid milestone reward verification, persistent currency (SCA coins) on
PostgreSQL, real-time multiplayer raids over Socket.io, and hardware spec simulation.



## Live demo

Deployed at **[https://pc.elcherlab.com](https://pc.elcherlab.com)**

You can try the web dashboard, real-time raids and the reward API there directly.


## About the original use-map

For the rules of the original **[SCA] Computer Upgrading V1.2.9** (currencies, shop, rebirth, part
tables and so on), see the documents below.

- [docs/original-map-v1.2.9.md](docs/original-map-v1.2.9.md) — original rules and the state of the web implementation
- [docs/spreadsheet-prices-v1.2.9.md](docs/spreadsheet-prices-v1.2.9.md) — frozen part purchase prices (spreadsheet)

## Features

| Feature | Description |
|------|------|
| **Daily raid rewards** | SCA coins for clearing milestones from floor 10 to 100 (every 10 floors). Resets once a day, with double-claim and race-condition protection |
| **Real-time raids** | Socket.io-based 4-player party simulation of the 100-floor boss raid |
| **Hardware simulator** | DPS and penalty calculations for CPU/GPU/RAM/cooler/motherboard/storage combinations |
| **Web dashboard** | `frontend/src/app.jsx` + `public/originalMapData.js` — V1.2.9 (1:1 minerals, cumulative saving, DDR and RAM slots, CPU hunting RAM, GPU tiers/display names, ◀▶ shop, AUTO, raids) |
| **Korean · English** | Switch with the 🌐 button in the header. Korean is the source text and the dictionary (`frontend/src/i18n.js`) layers English on top. The choice lives in localStorage only; between subdomains it is carried by a `?lang=en` link. Server error messages follow the screen language too — backend wording goes through `translateServerError()`, and the single sign-on service is passed `?lang=` so auth answers in that language itself |

## Tech stack

- **Runtime:** Node.js + TypeScript
- **HTTP:** Express
- **Real-time:** Socket.io
- **DB:** PostgreSQL (`pg`)
- **Frontend:** React 18 + Tailwind CSS (esbuild bundle, build time — no CDN, no in-browser Babel)

## Setup

### 1. Install dependencies

```bash
npm install
```

### 2. Configure environment variables

Copy `.env.example` to `.env`.

```bash
cp .env.example .env
```

| Variable | Default | Description |
|------|--------|------|
| `PORT` | `3000` | Server port |
| `NODE_ENV` | `development` | Runtime environment |
| `DB_HOST` | `localhost` | PostgreSQL host |
| `DB_PORT` | `5432` | PostgreSQL port |
| `DB_USER` | `postgres` | Database user |
| `DB_PASSWORD` | `postgres` | Database password |
| `DB_NAME` | `usemap_restore` | Database name |
| `DB_POOL_MAX` | `20` | Maximum connection pool size |
| `DB_SSL` | `false` | Whether to use SSL for a cloud database |
| `USE_RPC` | `false` | `true`: use the PL/pgSQL RPC / `false`: use a Node.js transaction |
| `ALLOWED_ORIGINS` | (per-environment default) | Allowed CORS/Socket.io origins, comma-separated. Unset in development allows everything; unset in production allows only `https://pc.elcherlab.com` |

### 3. Initialise the database

Create the database in PostgreSQL, then apply the schema.

```bash
createdb usemap_restore
psql -d usemap_restore -f schema.sql
```

### 4. Run the dev server

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) in your browser.

Production: [https://pc.elcherlab.com](https://pc.elcherlab.com)

### 5. Production build and run

```bash
npm run build
npm start
```

## API

### Health check

```
GET /health
```

**Example response**

```json
{
  "status": "ok",
  "timestamp": "2026-06-01T12:00:00.000Z"
}
```

### Claim a daily raid milestone reward

```
POST /api/raid/claim
Authorization: Bearer <token>
Content-Type: application/json
```

**Request body**

| Field | Type | Description |
|------|------|------|
| `currentFloor` | `number` | Floor reached (10-100, in multiples of 10) |

**Example request**

```json
{
  "currentFloor": 30
}
```

**Success response (200)**

```json
{
  "success": true,
  "message": "보상이 정상적으로 지급되었습니다.",
  "claimedCoins": 30,
  "newHighestFloor": 30,
  "currentTotalCoins": 30
}
```

**Reward rules**

- Each 10-floor milestone pays the **difference in the cumulative reward table**
  (floor 10 = 1,000 · floor 20 = 3,000 · … · floor 100 = 80,000)
- +100% reward per 10 million rebirth stat (`1 + rebirthStat / 10,000,000`)
- Re-requesting a floor at or below one already claimed is rejected
- `highestClaimedFloor` resets to 0 when the date changes
- Example: after claiming up to floor 80 today, clearing floor 100 pays the difference,
  80,000 − 40,000 = **40,000 coins**

> If the production database still has the old reward RPC (10 coins per 10 floors), apply
> `scripts/migrate_raid_rewards.sql` and then redeploy on Render.

### The data-export document (`/internal/export-user`)

This is the internal route the single sign-on service calls for "download my data". The document
comes in **two versions, Korean and English**: if the `lang` in the request body is `en` it answers
with English keys (anything else answers in Korean). The keys are not translated on the fly because
this is a file you download and keep — a key that changed with the language would no longer line up
with copies you already saved. The **rows themselves** (game progress, currencies) keep their DB
column names.

## Socket.io events

| Event (client → server) | Description |
|---------------------------|------|
| `joinRoom` | Join a raid room (`roomId`, `parts`). `auth: { token }` is required on connect |
| `readyStatus` | Toggle ready state (`isReady`) |

| Event (server → client) | Description |
|---------------------------|------|
| `room_state` | Room state broadcast (floor, boss HP, DPS, …) |
| `milestone_reward_claimed` | Result of a 10-floor milestone reward payout |
| `error_message` | Error message |

Default raid room id: `carry-room-100`

## Reward processing modes

`USE_RPC` selects how rewards are processed.

| Mode | `USE_RPC` | Description |
|------|-----------|------|
| Express TX | `false` (default) | `BEGIN` / `SELECT ... FOR UPDATE` / `COMMIT` from Node.js |
| Supabase RPC | `true` | Calls the `claim_daily_raid_reward()` PL/pgSQL function in `schema.sql` |

Both use the database server's `CURRENT_DATE` and prevent concurrency problems with row locks.

## Tests
